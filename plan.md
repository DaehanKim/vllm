# Full Logprobs (Spec v2.1) Implementation Plan

## Milestone 1 – API & CLI plumbing (Commit 1)
- [x] Introduce a gated flag (`--enable-full-logprobs-api`) in `vllm/entrypoints/openai/cli_args.py`, thread it through `api_server.py` and store it on `OpenAIServing` so the server can hard fail requests when the flag is absent. (commit 49fe8e5a7)
- [x] Extend the OpenAI protocol models (`vllm/entrypoints/openai/protocol.py`) with `FullLogprobsRequest`/`FullLogprobsResponse` dataclasses, add a `full_logprobs` field to `CompletionRequest`/`ChatCompletionRequest`, and expose an optional `full_logprobs` payload on `CompletionResponseChoice` and `ChatCompletionResponseChoice`. (commit 49fe8e5a7)
- [x] Push all teacher-mode validation (flag present, `max_tokens == 0`, `stream == false`, `n == 1`, prompt is token IDs vs text, dtype/format whitelist, position bounds) into the protocol/dataclass layer so any caller gets the same spec-synced error strings; `OpenAIServingCompletion` and `OpenAIServingChat` just surface the message when the CLI flag is off. (commit 32ffc9d46)
- [ ] Thread the validated `FullLogprobsRequest` object through the existing rendering path so each scheduled request carries a normalized teacher-mode descriptor (needed for later milestones) and add regression coverage in `tests/v1/entrypoints/openai/test_completion.py` (and the chat variant) for the new validation paths.

## Milestone 2 – Request metadata & buffer scaffolding (Commit 2)
- [ ] Define engine-level metadata in a new `vllm/full_logprobs.py` (or similar) module: a msgspec-friendly `FullLogprobsParams` struct, a `FullLogprobsChunk` struct (positions + row-major fp16 bytes), and a `FullLogprobsBuffer` helper keyed by `request_id` that stores `{position -> row data}` mappings and can emit `[L_eff, V]` slices respecting optional position filters.
- [ ] Extend `EngineCoreRequest`/`Request` (files `vllm/v1/engine/__init__.py`, `vllm/v1/request.py`) with an optional `FullLogprobsParams` payload that lives next to sampling params (rather than inside `SamplingParams`) so the worker layer knows which requests need full logprobs and what positions/dtype/format to keep.
- [ ] Update the `InputProcessor` (`vllm/v1/engine/input_processor.py`) and `OpenAIServing` base class so that, when a teacher-mode request is enqueued, we register it with the `FullLogprobsBuffer`, capture the target vocab size (`model_config.get_vocab_size()`), and ensure cleanup hooks exist for success/abort/timeouts.
- [ ] Teach `EngineCoreOutputs`/`RequestOutput` plumbing (`vllm/v1/engine/__init__.py`, `vllm/v1/engine/output_processor.py`, `vllm/v1/engine/logprobs.py`) to carry opaque `FullLogprobsChunk` streams from the backend to the AsyncLLM process and to feed them into the buffer as soon as they arrive.

## Milestone 3 – Backend data production (Commit 3)
- [ ] In each model runner (`vllm/v1/worker/gpu_model_runner.py` plus the CPU/TPU fallbacks), detect teacher-mode requests during prefill, compute `torch.log_softmax(logits, dim=-1)` in fp32, cast to fp16, move chunks to CPU immediately, and wrap them into `FullLogprobsChunk` objects that already contain the absolute token positions.
- [ ] Extend `ModelRunnerOutput`, the scheduler, and executor path (`vllm/v1/outputs.py`, `vllm/v1/core/sched/scheduler.py`, `vllm/v1/executor/*`, `vllm/v1/engine/core.py`) so those chunks survive the trip through the scheduler and land inside `EngineCoreOutputs.full_logprobs_chunks`.
- [ ] Ensure lifecycle management is solid: whenever a request finishes, aborts, or the engine resets caches, call `FullLogprobsBuffer.cleanup(request_id)` from the AsyncLLM side (update `output_processor.abort_requests`, `AsyncLLM.abort`, and DP wave teardown) so host memory is reclaimed even on error paths.
- [ ] Add small unit tests for the buffer (new test module under `tests/v1/full_logprobs/`) that feed multi-chunk, out-of-order streams and verify the resulting dense matrix, including `positions_filter` subset handling.

## Milestone 4 – Response assembly, encoding & docs (Commit 4)
- [ ] When a teacher-mode completion/chat request finishes, call `FullLogprobsBuffer.build_dense_array()` in `OpenAIServingCompletion`/`OpenAIServingChat`, ensure the array is contiguous `np.float16` (`'<f2'`, row-major), base64-encode the raw bytes, populate the new `choices[i].full_logprobs` payload, and make sure normal responses skip the field.
- [ ] Add API-level tests in `tests/v1/entrypoints/openai/test_completion.py` (and chat) that cover both token-ID prompts and the “text prompt (alignment not guaranteed)” case, decode the base64 matrix back to numpy, and compare against a reference PyTorch forward pass to confirm normalization/shape/positions.
- [ ] Document the feature in `docs/serving/openai_compatible_server.md` (request example, CLI flag, response schema) and add a release-note blurb in `RELEASE.md` clarifying the experimental nature and security implications.
- [ ] Verify the flow with the existing sample models (e.g., run `pytest tests/v1/entrypoints/openai/test_completion.py -k full_logprobs`) and add any missing assertions around usage accounting to ensure the final response's `usage` block still reflects prompt-only tokens.
